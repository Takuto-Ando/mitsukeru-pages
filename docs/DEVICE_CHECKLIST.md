## Google Driveの実送信を1件だけ確認する

1. 「絵の自動送信（研究用）」がONであることを確認する。カメラ画面で **シャッターを押す前** に、スマホの対象タブをMacからリモート検査する。iPhoneはSafariの「開発」メニューから端末を選ぶ。AndroidはUSBデバッグを有効にし、MacのChromeで `chrome://inspect/#devices` を開く。初回の接続設定時間は上の所要時間に含めない。 [SafariのWeb Inspector](https://webkit.org/web-inspector/enabling-web-inspector/) · [Android Chromeのリモート検査](https://developer.chrome.com/docs/devtools/remote-debugging/)
2. 対象タブのConsoleで次だけを実行し、表示されたIDを控える。直後の1回に限り、アプリが生成する記録IDをテスト用に置き換える。画面を再読み込みすると解除される。

```js
(() => {
  const original = crypto.randomUUID;
  const id = "TEST" + original.call(crypto).slice(0, 8) + "-" + Date.now();
  crypto.randomUUID = () => {
    crypto.randomUUID = original;
    return id;
  };
  console.log(id);
})();
```

3. シャッターを1回だけ押す。テスト用の絵を描いて「できた！」で保存し、ギャラリーで絵を確認する。テストには個人情報を含まない素材を使う。
4. 管理者の **ズーケッチ提出一覧** の記録ID列で控えたIDを検索する。該当行からDriveのPNGを開き、自分の絵であることを確認する。PNG名の末尾にはIDの先頭8文字が付く。行が見つからない場合は同じ絵を作り直す前に、スマホの接続と設定の送信待ち件数を確認する。

## 自動で確認できる範囲

公開用ビルドをローカルで起動し、端末相当のプロファイルを使って実行する。テストの撮影映像には見本画像、送信先にはモックを使用する。

```sh
npm run build
E2E_PREVIEW=1 npm run test:e2e -- tests/e2e/figma-v2-mobile-network.spec.ts
E2E_PREVIEW=1 E2E_SLOW_NETWORK=1 npm run test:e2e -- tests/e2e/figma-v2-mobile-network.spec.ts --project=chromium
```

3G相当は下り1.6 Mbps・上り0.75 Mbps・遅延150 msで、モデル取得の一時的な503と送信の応答停止を注入する。
