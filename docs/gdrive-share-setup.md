# 絵の自動送信（Googleドライブ集約）の設置手順

公開版で完成した絵を固定の Google Drive に自動送信する設定です。ブラウザは Cloudflare Pages の中継に送信し、Apps Script が Drive に保存します。

## 1. Apps Script を作る

1. https://script.google.com を開き「新しいプロジェクト」
2. 最初から入っているコードを全部消して、リポジトリの `gas/Code.gs` の
   内容を貼り付ける
3. 先頭の `TOKEN = "zooketch-2026"` を、自分の好きな文字列に変える
   （Cloudflare のシークレットと一致させる合言葉です）

## 2. ウェブアプリとして公開する

1. 右上の「デプロイ」→「新しいデプロイ」
2. 種類は「ウェブアプリ」
3. 設定：
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」を押す。初回は権限の承認（ドライブとスプレッドシートへの
   アクセス許可）が求められるので許可する
5. 表示される **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）
   をコピーする

## 3. Cloudflare 本番の設定

Cloudflare Pages の `zooketch` → Settings → Variables and secrets で、本番環境に次の2項目を設定し、再デプロイします。

| 変数 | 種別 | 値 |
| --- | --- | --- |
| `ZOOKETCH_SHARE_ENDPOINT` | Text | 手順2の Apps Script 実行 URL |
| `ZOOKETCH_SHARE_TOKEN` | Secret | 手順1の Apps Script トークン |

公開版の送信先とトークンは利用者の入力を必要としません。完成したスケッチを保存すると自動で送信します。通信が戻ったときや次の起動時に未送信分を再試行します。「設定」→「絵の自動送信（研究用）」で停止できます。既存端末でオフを選んだ場合も、その設定を維持します。研究で利用する場合は、参加者に送信内容・送信先・停止方法を事前に説明してください。

GitHub Pages 版も同じ Cloudflare 中継を使います。ブラウザが送るのは完成した絵（PNG）、線の座標、動物・課題の情報、記録IDと作成日時です。中継が Google 宛てリクエストに認証トークンを付け、受領確認後に端末の送信待ちから除きます。

## 4. 届いた絵の確認

- Googleドライブに **「ズーケッチ提出」** フォルダができ、絵（PNG）と
  線データ（JSON）が入ります
- スプレッドシート **「ズーケッチ提出一覧」** に、受信日時・動物・課題・
  絵へのリンクが1行ずつ追記されます

## 注意

- コードを直したら「デプロイ」→「デプロイを管理」から **新しいバージョン** で
  再デプロイしてください（URL は変わりません）
- トークンは簡易的な合言葉です。URL とトークンは研究関係者の外に
  公開しないでください
- 写真、声メモ、プロフィールID、自由記述は本番の中継に送信しません。

## Figma版の研究テスト起動

テスト用の開発サーバーは `npm run dev:study` で起動します。サーバー側の `.env.study.local` に次の2項目を設定します。管理者が用意した検証環境では、端末ごとの入力や送信ボタンの操作なしで、保存したスケッチを自動送信します。

```dotenv
ZOOKETCH_TEST_SHARE_ENDPOINT=設定したApps Scriptの実行URL
ZOOKETCH_TEST_SHARE_TOKEN=研究用のトークン
```

設定ファイルはGitの対象外です。トークンは開発サーバーだけが使い、ブラウザは同一オリジンの受け口にスケッチを送ります。学校や自宅の端末以外に提供する場合は、参加者を限定したHTTPS環境でサーバーを公開します。`npm run dev` は既存の開発設定を使い、両公開サイトは本番中継を使います。どの環境でも撮影写真は端末内に保存します。
